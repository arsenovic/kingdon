Algebra#

class kingdon.algebra.Algebra(p: int = 0, q: int = 0, r: int = 0, signature: list[int] = None, start_index: int = None, basis: list[str] = <factory>, registry: dict = <factory>, numspace: dict = <factory>, cse: bool = True, full_layout: bool = False, graded: dataclasses.InitVar[bool | None] = None, pretty_blade: str = '𝐞', large: bool = None, extra_types: dataclasses.InitVar[list | None] = None, types: list = <factory>, symbolcls: object = None, codegen_symbolcls: object = <bound method RationalPolynomial.fromname of <class 'kingdon.polynomial.RationalPolynomial'>>, lambdifier: Callable = None, wrapper: Callable = None, values_asarray: Callable = <class 'list'>, simp_func: Callable = <function Algebra.<lambda>>)[source]#

Bases: object

A Geometric (Clifford) algebra with p positive dimensions, q negative dimensions, and r null dimensions.

The default settings of cse = simplify = True usually strike a good balance between initiation times and subsequent code execution times.

Parameters:

  • p – number of positive dimensions.

  • q – number of negative dimensions.

  • r – number of null dimensions.

  • signature – Optional signature of the algebra, e.g. [0, 1, 1] for 2DPGA. Mutually exclusive with p, q, r.

  • start_index – Optionally set the start index of the dimensions. For PGA this defaults to 0, otherwise 1.

  • basis – Custom basis order, e.g. [“e”, “e1”, “e2”, “e0”, “e20”, “e01”, “e12”, “e012”] for 2DPGA.

  • cse – If True (default), attempt Common Subexpression Elimination (CSE) on symbolically optimized expressions.

  • full_layout – If True (default is False), every multivector carries the full layout of its type, so binary and unary operations are performed per type rather than per set of basis blades. This will still be more sparse than computing with a full multivector, but not as sparse as possible. It does however, vastly reduce the number of possible expressions that have to be symbolically optimized.

  • graded – Deprecated alias for full_layout, which raises a FutureWarning when given.

  • extra_types – multivector types to use in addition to the standard ones already provided by kingdon. See multivector types.

  • types – Complete list of multivector types to use. This will replace the standard ones. See multivector types.

  • simplify – If True (default), we attempt to simplify as much as possible. Setting this to False will reduce the number of calls to simplify. However, it seems that True is still faster, because it keeps sympy expressions from growing too large, which makes both symbolic computations and printing into a python function slower.

  • wrapper – A function that is always applied to the generated functions as a decorator. For example, using numba.njit as a wrapper will ensure that all kingdon code is jitted using numba.

  • values_asarray – An array construction function that is always applied to values of a multivector upon creation of a new mv. For example, this could be numpy.array or torch.asarray to ensure that mv’s are always your favorite arrays.

  • symbolcls – The symbol class used for symbolic multivectors. By default, this sympy.core.symbol.Symbol.

  • codegen_symbolcls – The symbol class used during codegen. By default, this is our own fast RationalPolynomial class.

  • lambdifier – The function that turns the symbolic expressions of an operation into a python function. Defaults to lambdify(); provide your own to take over code generation entirely.

  • simp_func – This function is applied as a filter function to every multivector coefficient.

  • pretty_blade – character to use for basis blades when pretty printing to string. Default is 𝐞.

  • large – if true this is considered a large algebra. This means various cashing options are removed to save memory, and codegen is replaced by direct computation since codegen is very resource intensive for big expressions. By default, algebras of \(d > 6\) are considered large, but the user can override this setting because also in large algebras it is still true that the generated code will perform order(s) of magnitude better than direct computation. A large algebra has no multivector types: every multivector is a MultiVector, and types, extra_types and full_layout are therefore not available.

add_operator(expr=None, /, *, name=None, symbolic=False, codegen_symbolcls=None, lambdifier=None, wrapper=None, values_asarray=None, **lambdifier_kwargs)[source]#

Add a new operator to the algebra, compiled to optimize its execution times. The function must accept multivectors as input arguments and is assumed to either return a single multivector or to set one of the input multivectors.

Examples:

@alg.add_operator(symbolic=True)
def proj(a, b):
    return (a | b) / b

@alg.add_operator(symbolic=True)
def proj_allocated(a, b, c):
    c.set((a | b) / b)

@alg.add_operator(symbolic=True)
def proj(mvs: MultiVector[2]):
    a, b = mvs
    return (a | b) / b

The examples above show three different ways to compile a function. Firstly and most straightforwardly, simply decorate a function that takes MultiVectors as input and a single MultiVector as output. Secondly, rather than returning a MultiVector, one can modify one existing MultiVector in place using the set method. This is useful in combination with e.g. pre-allocated memory like is sometimes the case with PyTorch tensors. Thirdly, using the type annotation MultiVector[N] we can signal to compile that the function takes a multivector of shape (:, N).

With default settings (symbolic=False), the decorator will ensure that every GA unary or binary operator is replaced by the corresponding numerical function, and produces numerically much more performant code. However, when symbolic=True the expression is symbolically optimized before being turned into a numerical function. This typically results in even more performant code, at the expense of extra cost for the first execution.

Parameters:

  • expr – Python function of a valid kingdon GA expression.

  • name – (optional) name by which the function will be known to the algebra. By default, this is the expr.__name__.

  • symbolic – (optional) If true, the expression is symbolically optimized. By default this is False, given the cost of optimizing large expressions.

  • codegen_symbolcls – (optional) The class to use for symbolic multivectors. By default the codegen_symbolcls from Algebra is used.

  • lambdifier – (optional) The function that turns the symbolic expressions into a python function. By default the lambdifier from Algebra is used.

  • wrapper – (optional) The wrapper function used to wrap the compiled function. By default the wrapper from Algebra is used.

  • values_asarray – (optional) The values_asarray function used to cast the values to the correct array type. By default values_asarray from Algebra is used.

  • lambdifier_kwargs – Any remaining keyword arguments are passed on to the lambdifier. For the default lambdify() these are printer and func_printer, the sympy style printers used to print the expressions.

compile(expr=None, /, *mvs, symbolic=True, lambdifier=None, wrapper=None, values_asarray=None, **lambdifier_kwargs) → CompiledExpression[source]#

Compile a GA expr with specific symbolic multivectors. For typical use cases you’ll probably want to use Algebra.add_operator instead, since that does not require you to provide the symbolical multivectors yourself, and it caches the resulting compiled functions so you don’t have to track them yourself. However, the finer level of control of compile is extremely powerful in certain use cases. For example, consider that we need to repeatedly rotate the unit vectors of our algebra in order to compute the evolution of the frame vectors:

def rotate_blade(R, blade):
    return R >> blade

alg = Algebra(3)
R = alg.bireflection(...)  # Either a symbolic or a numeric rotation
e1 = alg.vector(e1=1)
e1_prime = rotate_blade(R, e1)

By inspecting the code generated in alg.sw[R, e1].func or by looking at its docstring alg.sw[R, e1].func.__doc__, we find that the generated code uses 14 muls and 5 adds. (Mind you that the built-in sw operator already benefits from CSE; without it the same expression needs 18 muls and 7 adds.) However Algebra.add_operator can never use the runtime values of the multivector coefficients, whereas we know that we only want to rotate unit vectors. So we can use Algebra.compile to generate an even more specialized function:

rotation = alg.bireflection(name='R', symbolcls=alg.codegen_symbolcls)
e1 = alg.vector(e1=1)
rotate_e1 = alg.compile(rotate_blade, rotation, e1)  # compile the function for these specific mvs.
e1_prime = rotate_e1(R, e1)

If we look at rotate_e1 we find that it has only 9 muls and 5 adds! Compiling common operations involving constant multivectors such as frames can therefore be highly beneficial.

Beware that rotate_e1 should not be used on non-unit vectors, so the onus falls on you to enure you only call it with appropriate vectors.

Parameters:

  • expr – Python function of a valid kingdon GA expression.

  • mvs – The symbolic multivectors to compile expr for.

  • symbolic – (optional) If true (default), the expression is symbolically optimized.

  • lambdifier – (optional) The function that turns the symbolic expressions into a python function. By default the lambdifier from Algebra is used.

  • wrapper – (optional) The wrapper function used to wrap the compiled function. By default the wrapper from Algebra is used.

  • values_asarray – (optional) The values_asarray function used to cast the values to the correct array type. By default values_asarray from Algebra is used.

  • lambdifier_kwargs – Any remaining keyword arguments are passed on to the lambdifier. For the default lambdify() these are printer and func_printer, the sympy style printers used to print the expressions.

Returns:

Instance of CompiledExpression.

graph(*subjects, graph_widget=None, **options)[source]#

The graph function outputs ganja.js renders and is meant for use in jupyter notebooks. The syntax of the graph function will feel familiar to users of ganja.js: all position arguments are considered as subjects to graph, while all keyword arguments are interpreted as options to ganja.js’s Algebra.graph method.

Example usage:

alg.graph(
    0xD0FFE1, [A,B,C],
    0x224488, A, "A", B, "B", C, "C",
    lineWidth=3, grid=1, labels=1
)

Will create

If a function is given to Algebra.graph then it is called without arguments:

def graph_func():
    return [
        0xD0FFE1, [A,B,C],
        0x224488, A, "A", B, "B", C, "C"
    ]

alg.graph(
    graph_func,
    lineWidth=3, grid=1, labels=1
)

This can be used to make animations in a manner identical to ganja.js by making graph_func depend on time and setting animate=True.

Subjects

The following types are accepted as positional arguments:

  • MultiVector: rendered according to its grade and the algebra’s signature, e.g. as a point, line, plane, circle, sphere, etc. A multivector with array-valued coefficients (e.g. numpy arrays) is unpacked into the individual multivectors it represents, see Meshes and point clouds.

  • int: a hexadecimal color such as 0x224488, which sets the color of all subsequent subjects until the next color.

  • str: a label, drawn at the position of the last drawn subject. Strings starting with "<" are inserted verbatim as SVG, strings enclosed in $ are typeset as TeX (when a TeX renderer is loaded on the page), and strings starting with "_" are not drawn but do advance the text cursor.

  • list or tuple: two multivectors are drawn as a line segment, three or more as a filled polygon. Lists may be nested, and may contain any of the types above.

  • Callable: called without arguments, and the result is graphed. A single callable returning a list of subjects is typically used for animations; callables nested deeper in the input are re-evaluated in the same way.

Multivectors passed directly as positional arguments (i.e. not nested inside a list) may be draggable: dragging them in the canvas writes the new coefficients back into the Python object in-place. In PGA only points (grade \(d-1\)) are draggable, in conformal algebras (conformal=True) only grade 1 elements are draggable. Shaped multivectors are never draggable.

Meshes and point clouds

A multivector of shape (N, ...) is spliced into the list of subjects instead of being drawn as a single element, so a mesh or point cloud is a single subject rather than thousands. Just like a python list, the trailing axis decides what is drawn: shape (N,) gives \(N\) separate elements (a point cloud), (N, 2) gives \(N\) line segments (edges), and (N, 3) gives \(N\) filled triangles (faces). Given a vertices array of shape \((N, 3)\) and an integer faces array of shape \((M, 3)\) indexing into it:

v = alg.upoint(vertices.T).dual()  # Point[(N,)]
facets = v[faces]                  # Point[(M, 3)]
alg.graph(0xEE8888, facets, 0x000000, v, pointRadius=0.2)

Build the points as upoint(...).dual() rather than point(vertices.T): the positional values of a type are its free coefficients in layout order, which for a Point in Algebra(3, 0, 1) is \((-z, y, -x)\), not \((x, y, z)\). Note also that ganja.js only renders the lexicographical basis, so use Algebra(3, 0, 1, extra_types=[...]) and not Algebra.fromname('3DPGA').

Options

All keyword arguments are passed on to ganja.js’s Algebra.graph directly, with the exception of camera, up, width, height and style, which are (also) interpreted by kingdon. As such, kingdon automatically inherits all the options from ganja.js. The most useful ones are mentioned in the list below.

Parameters:

  • *subjects – The subjects to be graphed, see above.

  • camera – A motor which places the camera at the desired viewpoint. Defaults to the identity motor.

  • width – CSS width of the canvas, e.g. '600px' or '100%'. Defaults to 'min( 100%, 1024px )'.

  • height – CSS height of the canvas, e.g. '400px'. Defaults to 'auto', in which case the aspect ratio of 16 / 6 determines the height.

  • style – Dictionary of additional CSS properties (camelCased, as in JS) applied to the canvas, e.g. {'background': 'black', 'aspectRatio': '1 / 1'}.

  • animate – If truthy, the scene is redrawn every frame and all callables are re-evaluated, which is what drives animations. Defaults to False, in which case the scene is only redrawn when a subject changes or the user interacts with it.

  • grid – Draw a grid.

  • labels – Label the grid lines.

  • gridSize – Size of the grid in world units.

  • gridFontSize – Scale of the grid labels.

  • scale – Zoom level of the scene (2D/SVG rendering), default 1.

  • lineWidth – Line width multiplier.

  • pointRadius – Point radius multiplier.

  • fontSize – Label size multiplier.

  • conformal – Use the conformal renderer, needed for CGA.

  • up – The ‘up’ (\(C\)) function, a callable taking Euclidean coordinates and returning the corresponding element of the (larger) embedding space. Providing an up function invokes ganja’s OPNS renderer, which can render any algebra, e.g. CGA, 2D CSGA, 3D CCGA, 3D Mother Algebra. The function is traced symbolically and compiled to GLSL, so it must consist of algebraic operations only. See the teahouse for examples.

  • ipns – Interpret the subjects as IPNS (dual) elements instead of OPNS.

  • gl – Force the WebGL renderer (the default in 3D), which supports raytraced surfaces.

  • spin – Rotate the camera continuously at the given rate (WebGL only).

  • thresh – Threshold used by the raymarcher to decide when a surface is hit.

  • graph_widget – The graph widget to use. Defaults to kingdon.graph.GraphWidget.`

  • **options – Any other option supported by ganja.js’s Algebra.graph, such as alpha, cull, noZ, htmlText, devicePixelRatio, clip, still.

Returns:

A GraphWidget displaying the scene with ganja.js. The update() method can be used to redraw an existing figure.
